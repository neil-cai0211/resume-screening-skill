# 建立岗位评分标准

## 收集资料

- **对话**。确认岗位编号、主要工作、关键结果、必须条件及推荐对象。先围绕影响筛选结论的问题核实。来源写对话记录和取得时间。
- **文档**。读取指定 JD、人才画像、胜任力模型的相关章节。在私有配置中保留版本、日期和章节或文档入口。
- **薪人薪事**。用 Ego Lite 和用户授权的登录态读取指定岗位，操作限于岗位描述和来源信息。按[下方路径](#薪人薪事只读读取)定位记录，遇到登录、权限或描述缺失时，用用户提供的文档、文本或口述补齐。

### 薪人薪事只读读取

1. 从管理首页展开顶部「导航」，选择「招聘 → 需求」或「招聘 → 职位」。首页的「我的招聘」通向员工端的内推与应聘。职位列表选择「全部」，用岗位全称、已确认别名和关键词查找。需求列表按未开始、进行中、已关闭查看，也可按需求编号查找。等列表加载完成后核对标题、状态和记录编号。
2. 在职位列表，从目标记录自身的「更多 → 编辑」打开已保存表单，核对表单上的职位名称，再读取「职位描述」。点职位标题会打开该职位的简历列表。右侧菜单超出窗口时，可扩大视图或横向滚动。打开表单后只读取现有字段。
3. 记录岗位名、来源入口、可核实的记录编号或链接、读取日期和描述正文。内部记录与正文留在私有工作区。同名或多条记录请招聘方选定。EHR 描述与已生效标准出现门槛差异时，列出双方原文，交招聘方确认后再发布新版本。

对照不同材料，区分公开 JD 里的任职要求、人才画像里的偏好和胜任力模型里的行为。比如「带队经验优先」可以作为加分项。改成硬门槛需要招聘方确认。材料中没写某项经历，标证据不足。涉及工作时间、薪资预期、临场能力等信息，按岗位流程另行核实。

## 起草与确认

以 [电话销售样例](../examples/DEMO-SALES.json) 为配置结构参考。内部分值可以按百分制或岗位约定的总分，推荐线须在评分范围内。

| 字段 | 填写方式 |
| --- | --- |
| `id` / `title` / `aliases` | 稳定岗位号、显示名及允许自动匹配的完整别名 |
| `version` / `status` | 新标准先为 `draft`，招聘方确认后写 `approved`，并补齐 `approval.by`、`approval.at`、`approval.record` |
| `sources` | 每份资料写 `type`、`locator`，有章节或日期时继续补充 |
| `references` | 选填。需要给模型直接读的依据文件，相对仓库或私有岗位配置目录。只放岗位依据 |
| `dimensions` | 维度 ID、名称、满分和分档说明。写清怎么从简历看到该项，以及什么证据计多少分 |
| `checks` | 每项写 ID、名称、证据要求，以及触发某状态时的处理。没有门槛可留空列表 |
| `threshold` | 岗位满分范围内的推荐线，达到该线且没有阻挡规则即推荐 |
| `output` | 面试官版评语栏目、写作要求及是否展示总分 |

正常门槛用 `met`（符合）、`unmet`（明确不符）、`unknown`（证据不足）。红线如果写的是「是否命中某行为」，`met` 表示命中，可据明确证据判不合适，`suspected` 表示有疑点。用 `actions` 明示每个状态的后续动作，可选「不合适」「待定」「待补材料」，未配置的状态仅记录。程序先检查明确拒绝，再看总分和组合规则，最后处理暂缓和补材料。多个暂缓条件按岗位配置顺序取第一个，其余仍留在记录中。

招聘方确认时核对资料、评分档位、红线、未知证据处理、推荐线和摘要栏目。后续更新用新版本和对应确认记录。技术验证使用 `--demo` 即可加载草案，正式运行仅加载已确认的私有岗位标准。发送时段和面试官保存在单独的私有配置中，并通过首批预览确认。
