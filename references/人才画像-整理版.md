## 一、这个岗位要干什么（一句话版）
接手一套**正在运行**的餐饮 POS 后端，把它"收干净"：不是从零搭新系统，是在老系统上边跑边改。

两件事：
1. **代码仓库合并**：14 个 Git 仓库合成 1 个（monorepo），Maven 统一版本，CI（自动构建流水线）只构建改动到的部分。
2. **架构四步改造**：① 先补熔断和安全漏洞 → ② 下单/支付/积分改成"事件 + 补偿"方式 → ③ 划清各服务的数据库边界 → ④ 统一依赖和发布。

技术栈：Java 8、Spring Boot 2.2、Spring Cloud、Nacos、Feign、MyBatis-Plus、RabbitMQ、GitLab。

## 二、硬性条件（5 条，必须有）
| # | 条件（原文） | HR 能看懂的说法 | 简历里找什么证据 |
|---|---|---|---|
| H1 | 在在跑的交易系统上做过微服务改造，能讲清一次一致性或故障隔离怎么落地、怎么回滚 | 在**已上线、有真实交易**的系统里，把大系统拆成小服务；并处理过"数据对不上"或"一个服务挂了别拖垮全部"的问题 | 项目经历里同时出现：①线上交易/订单/支付系统；②"微服务拆分/改造"；③一致性（分布式事务、最终一致、对账）或故障隔离（熔断、限流、隔离）的具体做法；最好有灰度、回滚字样 |
| H2 | 熟悉 Spring Cloud + Feign，能补超时、熔断、降级 | 会用这套框架做服务之间调用，并会设"等太久就放弃、出错就断开、断开后给个兜底结果" | Spring Cloud、Feign 出现在项目里（不只技能栏）；有超时配置、熔断、降级，常见组件名：Sentinel、Hystrix（已停止维护）、Resilience4j |
| H3 | 处理过「本地事务里调远程接口」的脏数据，用过消息队列做异步和补偿 | 遇到过"自己这边数据库写了一半、调别的服务失败了，导致数据脏"，并用消息队列改成异步、失败后补偿回来 | 关键词：脏数据、数据不一致、事务消息、本地消息表、补偿、重试、幂等、对账；消息队列用在业务流程里；【公司】 用 RabbitMQ，「本地消息表 / outbox」最对口，RocketMQ 事务消息次之，只写 Seata 算提及 |
| H4 | 做过多仓库合并或 Maven 多模块治理（父 POM、版本锁定、CI） | 管过"很多代码仓库/模块怎么统一管理、统一版本、自动构建" | monorepo、仓库合并、Maven 多模块、父 POM、dependencyManagement / BOM、版本统一、CI/CD（GitLab CI、Jenkins） |
| H5 | 能自己进代码拆大类，不是只出方案 | 自己动手改代码，不是只写方案、画图交给别人做 | 描述用"我重构/我拆分/我实现"，有具体代码层面的动作（拆分大类、重构模块、代码量、提交）；当前或近期仍在写代码 |
